# セキュリティと権限

最終更新：2026-08-14

この文書は、現在の実装が行う認証と認可を記録します。
Firestore には Service Account で接続するため、通常の API リクエストに Firestore Security Rules は適用されません。

## 認証

Firebase Authentication のメールアドレスとパスワード認証を使います。
バックエンドはすべての `/apiv1/*` で ID トークンを検証し、`email_verified` が `true` の利用者だけを受け付けます。

Firebase の公開鍵は Cloudflare KV にキャッシュします。
フロントエンドはトークンを 10 分ごとに更新し、ログアウト時に API トークンと React Query キャッシュを破棄します。

## グループロール

| ロール | 許可される主な操作 |
| --- | --- |
| `VIEW` | 所属グループの検索とスカウト閲覧 |
| `EDIT` | VIEW の操作、スカウト作成と更新、共有管理 |
| `ADMIN` | EDIT の操作、削除、移管、グループ設定、メンバーと招待の管理 |

ロールの継承を共通ミドルウェアで計算しているわけではありません。
各ハンドラーが許可するロールの配列を明示し、`isInRoleOnGroup` で所属とロールを同時に確認します。

## スカウト共有

共有ロールは `VIEW` と `EDIT` です。
`VIEW` はスカウト取得、`EDIT` は取得と更新を許可します。

通常画面から作る共有は常に `VIEW` です。
データ形式は `EDIT` も扱えますが、通常 API に共有ロールを変更するエンドポイントはありません。

共有の作成と削除は、対象スカウトの所属グループで ADMIN または EDIT の利用者だけが実行できます。
新しい共有の作成には、Group の `allowShare` も必要です。

## グループ管理の防御

- 自分自身の招待とスカウト共有を拒否します。
- 自分自身をメンバー一覧から削除できません。
- 自分自身のグループロールを変更できません。
- 同じグループへの所属と招待の重複を拒否します。
- 同じスカウト共有の重複を拒否します。
- User 削除とグループ脱退では、最後の ADMIN が消えないことを確認します。
- 所属、招待、共有の各配列は 10 件を上限とします。

メンバー削除とロール変更では操作する ADMIN 自身を対象にできないため、操作後も少なくともその ADMIN が残ります。

## God モード

`auth.isGod` が `true` の User だけが `/apiv1/god/*` を使えます。
God API は通常のグループ認可を通さず、Scout、Group、User の検索、全体置換、削除を行います。

この権限はアプリケーション全体に影響するため、付与先を運営管理者に限定します。

## CORS

本番環境はクロスオリジン要求を許可しません。
`IS_DEV` が `TRUE` の環境だけはオリジンを `*` にします。
